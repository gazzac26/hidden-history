# HIDDEN HISTORY
# CONTENT AND DATA CORRECTION PROCEDURE

Status: INTERNAL / PRE-BETA / WORKING DRAFT

---

## 1. PURPOSE

This procedure explains how Hidden History should handle reports that
vehicle information or other displayed information may be incorrect.

---

## 2. IMPORTANT DISTINCTION

Hidden History may display information supplied by external data
providers.

Hidden History may not control the underlying source record.

A correction request must therefore establish whether the issue is:

1. A source-data issue; or
2. A Hidden History processing/display issue.

---

## 3. USER REPORT

Users should provide:

- Relevant vehicle registration
- Description of the suspected error
- Screenshot where appropriate
- Supporting evidence where available
- Account information where necessary

---

## 4. INITIAL REVIEW

Determine:

- Which source supplied the information
- What Hidden History received
- What Hidden History displayed
- Whether processing changed the information
- Whether the source record appears incorrect

## 7. MOT RECORDS

MOT information should not be manually altered merely because a user
disagrees with a historical MOT result.

Where an MOT record appears incorrect, the appropriate source-provider
correction process should be followed.

---

## 8. ANALYSIS RESULTS

If the user believes an analysis result is incorrect:

- Identify the input data.
- Identify the analysis rule or process involved.
- Determine whether the result is operating as designed.
- Correct a technical error where identified.

The analysis must not be represented as a definitive statement of
vehicle condition.
