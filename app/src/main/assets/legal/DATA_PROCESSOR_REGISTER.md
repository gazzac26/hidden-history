## 3. CURRENT PROCESSOR / SERVICE REGISTER

### Supabase

Role:

Database, authentication and backend service provider.

Processing:

Account information, saved reports and other application data required by the production architecture.

Position:

Processor where Supabase processes personal data on Hidden History's documented instructions for the relevant service.

Action:

Verify the current production Supabase terms/DPA and record the applicable contractual arrangement.

---

### Google Play / Google Play Billing

Role:

Application distribution and paid-purchase infrastructure.

Processing:

Purchase, entitlement and related account/payment information actually made available through Google services.

Position:

The precise controller/processor allocation depends on the data flow and service involved. Hidden History must not describe Google as a processor for data that Google processes for its own independent purposes.

Action:

Document the actual production data received by Hidden History and the relevant Google terms.

---

### Gemini

Role:

Pro advert-analysis service.

Processing:

Hidden History's own advert-analysis results, the raw advert supplied for analysis and relevant vehicle data required for the analysis.

Hidden History does not intentionally send user account/profile information to Gemini.

Advert text may contain personal information that a seller has included in the advert. Hidden History cannot guarantee that advert content contains no personal information.

Position:

Verify the production Gemini service terms and data-processing role before beta sign-off.

---

### eBay API / affiliate service

Role:

Vehicle-parts sourcing.

Processing:

Only information necessary for the parts-link functionality should be passed to the service.

Position:

Verify the actual production API/affiliate arrangement and any applicable privacy role before beta sign-off.

## 4. DATA SOURCES THAT ARE NOT PROCESSORS

### DVLA

Provides official vehicle information used by Hidden History.

DVLA is treated as an external source of vehicle data, not automatically as a processor acting on Hidden History's behalf.

### DVSA / MOT

Provides official MOT information.

DVSA is treated as an external source of vehicle data, not automatically as a processor acting on Hidden History's behalf.

## 6. PROCESSOR MANAGEMENT

For each actual processor, Hidden History should maintain evidence of:

- Provider identity
- Service used
- Data processed
- Purpose
- Contractual terms/DPA where applicable
- Security provisions
- Subprocessor arrangements
- International-transfer position
- Deletion/retention position
- Support for data-subject rights

---

## 7. SUBPROCESSORS

Where a processor uses subprocessors, the applicable provider terms must be reviewed and material subprocessor changes monitored in accordance with the contract.

Hidden History should not assume that a processor's subprocessor list is irrelevant merely because Hidden History does not contract directly with each subprocessor.

---

## 8. DELETION

Where Hidden History requests account deletion, applicable processors should support deletion of account-linked personal information in accordance with their contractual obligations and applicable law.

---

## 9. REVIEW

Review this register when:

- A provider is added
- A provider is removed
- Processing changes
- A new data category is introduced
- International processing changes
- A new subprocessor becomes relevant
- MIB/MIAFTR becomes operational
- The legal operator changes
