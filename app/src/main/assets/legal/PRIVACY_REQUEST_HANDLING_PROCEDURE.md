# HIDDEN HISTORY
# PRIVACY REQUEST HANDLING PROCEDURE

Status: PRE-BETA / WORKING DRAFT

---

## 1. PURPOSE

This procedure explains how Hidden History will handle privacy and
data-protection requests from users.

---

## 2. REQUEST TYPES

Requests may include:

- Access requests
- Correction requests
- Erasure requests
- Restriction requests
- Objection requests
- Data portability requests
- Consent withdrawal where applicable

## 4. REQUEST RECEIPT

When a request is received:

1. Record the date received.
2. Record the request type.
3. Record the requester's contact details.
4. Verify identity where reasonably necessary.
5. Determine what information is involved.
6. Determine whether the request is valid.
7. Identify any applicable exemptions or limitations.
8. Respond within the applicable legal timeframe.

---

## 5. IDENTITY VERIFICATION

Hidden History should take reasonable steps to ensure information is
not disclosed to an unauthorised person.

Verification should be proportionate.

Do not request excessive identification information.

---

## 6. ACCESS REQUEST

For an access request:

- Identify relevant personal information.
- Search applicable systems.
- Review third-party information.
- Check for information that cannot lawfully be disclosed.
- Prepare the response.
- Record completion.

---

## 7. CORRECTION REQUEST

Where a user believes personal information held by Hidden History is
incorrect:

- Identify the disputed information.
- Determine whether Hidden History controls the information.
- Correct information where appropriate.
- If the underlying source controls the record, explain the position
  and direct the user to the relevant source where appropriate.

---

## 8. ERASURE REQUEST

When deletion is requested:

- Verify the request.
- Identify information that should be deleted.
- Identify information that must lawfully be retained.
- Delete or anonymise appropriate information.
- Record completion.
